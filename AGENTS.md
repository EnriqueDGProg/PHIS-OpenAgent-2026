## Engineering and competition safeguards
- Validate event requirements against published official rules before implementation. Downloaded working drafts are not independently binding.
- Clearly distinguish existing PHIS capabilities from new functionality implemented in the official competition window, preserving commit history and evidence.
- Public demo datasets must be synthetic and explicitly labeled. Never commit real user health data, private SQLite databases, exports, tokens, or personally identifying data.
- PHIS Discovery owns deterministic scientific/statistical analysis. LLMs must not invent measurements, findings, confidence, causal claims or medical advice.
- Deliver an honest, runnable agent demonstrating actual tool usage, evidence lineage, abstention when evidence is weak, tests, and a polished accessible UI.
- Document dependencies and external services; require reviewed pull requests and verification before merge/deployment.
- Follow Venture OS principles: reuse, minimum recurring cost, security, deterministic tools before expensive AI.
- Before building competition-specific features, verify start dates and preexisting-code rules against official sources.
