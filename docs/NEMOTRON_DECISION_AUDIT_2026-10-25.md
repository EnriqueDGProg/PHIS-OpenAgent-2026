## Decision diagnosis

There are two distinct findings:

1. **The abstention was implemented correctly as a safe stop.** Discovery and the recheck passed; the model returned a valid `abstain`; the [orchestrator withholds user-facing findings](https://github.com/EnriqueDGProg/PHIS-OpenAgent-2026/blob/b6e3d48f66ba99b22aff91359771316208d52727/src/phis_open_agent/nightshift_agent.py#L619-L634). It never promotes weak coverage or uses model text as a measurement.
2. **The critique protocol has an auditability defect and an unreasoned absolute veto.** Even a purely descriptive observation is hidden unless the model says `accept`; the one-key schema cannot distinguish a substantive evidence contradiction from caution about non-causality or an arbitrary refusal. The provenance-rich packet does not remedy missing decision rationale. This is not evidence that the model was scientifically wrong, and automatically overriding it would be a safety downgrade.

| Case | Current PR #42 behavior | Defensible protocol target (proposal, **not implemented**) |
| --- | --- | --- |
| Grounded descriptive change and qualified association, all PHIS gates pass | Model `accept` publishes typed Discovery result; model `abstain` suppresses everything with generic reason. | Record a bounded reason category and cited evidence IDs for any veto; validate category and source linkage before deciding whether to withhold each claim type. Never turn a model refusal into an automatic accept. |
| Unsupported association or weak/contradictory source evidence | Deterministic Discovery classification and provenance gates constrain findings; the model may further abstain. | Preserve deterministic exclusion and require any critique to cite the exact conflicting signal or gate; abstain if the citation is invalid. |
| Coverage fails, clinical request, malformed or unavailable inference | Existing deterministic or fail-closed block; no scientific promotion. | Preserve the same fail-closed behavior and explicit reason codes. |

The proposed change requires an independently reviewed critique contract, validation and a bounded live acceptance run. It is **not** justified by the captured one-key receipt alone, so this audit makes no runtime fix and no hosted call.
