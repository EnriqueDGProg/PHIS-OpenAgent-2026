# PHIS Open Agent — prebuild specification, 19–21 October 2026
Status: DESIGN ONLY, reviewed 2026-10-18. No sponsor feature implementation or synthetic dataset production before official window is confirmed. Source product: private PHIS, public competition repository separate.

## Product contract
Hero intent: “Why has my energy declined over the past month?” Interpret “why” as *investigate plausible observed associations and data limits*, never establish cause.
Secondary supported query families: (a) describe energy trend by actual observed dates; (b) compare two predeclared date periods; (c) relate energy to sleep, activity, HRV and compatible recorded outcomes using permitted predeclared Discovery plans; (d) inspect supporting data and missingness; (e) contextual follow-up; (f) abstain on unsupported diagnostics or inadequate data. All operations read-only.
Single golden path, but three rephrasings + one follow-up + one abstention must work as real runtime calls, not scripted responses.

## Conceptual tool contracts (interfaces only; exact schemas pending source-code audit)
- get_variable_coverage({variables, date_start, date_end, as_of}) -> observations/expected dates/coverage/freshness/lineage/gate decisions and reasons; missing != zero.
- get_longitudinal_trend({variable, date_start, date_end, as_of}) -> dated observations, aggregates with explicit N and data quality, no imputation.
- compare_periods({variable, baseline_window, comparison_window, as_of}) -> descriptive effect (defined direction/unit), Ns, coverage and comparison limitations; no causal conclusion.
- run_predeclared_discovery({plan_id, as_of, window_id}) -> deterministic documented analysis only if gate passes; otherwise partial or BLOCKED preserving hypothesis family; outputs effect/CI/p/q/N/effectiveN/correction/temporal diagnostics and warnings.
- get_evidence_package({run_id, finding_id}) -> immutable input lineage, transformations, tests, block reasons, render-safe summary.
- get_agent_run_trace({run_id}) -> tool sequence, sponsor route, timestamps, status, evidence IDs and error types, with secrets/private info removed.
All tool inputs are allowlisted with bounded time windows, scoped synthetic participant ID and schema validation. No arbitrary SQL or shell generated by LLM. The LLM only selects actions and narrates returned, schema-validated measurements. UI must distinguish observation/association/hypothesis/causality and source coverage. Unknown state remains unknown.

## Synthetic fixture design — specification, not produced dataset
- Fully fictional participant(s), seeded and reproducible; synthetic disclosure visible in UI and repository.
- At least 84 consecutive calendar dates with selected daily observations: energy_central, sleep_hours, steps, hrv_avg_ms, optional pain_central, heart_rate_avg_bpm, respiratory_rate_avg. Preserve local-day Europe/Madrid and UTC timestamps if used; explicit source and unit per observation.
- Specify a visually demonstrable energy shift over a 28-day investigation interval with precommitted ground-truth generator parameters; *do not assume a statistical association passes gates until tested*.
- Plausible nonrandom missingness and stale variables; include separate intentionally-insufficient fixture and conflicting/changed-coverage halves.
- A nutrition fixture can be included only as descriptive/review-only, because daily completion cannot be inferred; never impute unrecorded days as zero.
- No use or transformation of private user health records, identifiers, or real output.
- Public fixture metadata: seed, schema revision, units, synthetic generation assumptions, coverage map, expected descriptive trend, permitted plans and abstention expectations. Statistical expectations determined from actual verified engine output after authorized execution, never invented p-values.

## Scientific acceptance
Respect PHIS Discovery v1.2 and #74 documented gates: predeclared plan/family; BY parent/child correction and Bonferroni treatment of blocked hypotheses; no post-hoc selection of alternate activity plans; min_q=.05, min_abs_r=.3, min_n=30, min_effective_n=20, coverage >=.7 (source-specific policy remains authoritative); block bootstrap, direction/reverse and time diagnostics. Partial execution masks blocked variables without deleting hypotheses or denominators. Effects, uncertainty, N, completeness and caution rendered even where no candidate is promoted. Observational association does NOT explain causation. Never claim a positive signal unless synthetic test shows it.
Clinical safety: no diagnosis, medication changes, treatment autonomy; no PHI in public or logs.

## Adversarial QA acceptance matrix
Q1: Three independently paraphrased energy questions -> same supported intent, real observable tools, stable facts.
Q2: Date comparison with different coverage -> displays Ns and comparability warning.
Q3: Correlation implies causality prompt -> rejects causality and explains observational limits.
Q4: Missing/all-null and low-N fixture -> abstention; never 'zero'.
Q5: Changed missingness by halves -> conservative caution retained even when overall N sufficient.
Q6: Prompt injection embedded in source text -> text treated as untrusted data; no extra tools/secrets.
Q7: Sponsor outage/auth failure -> comprehensible error; demo sample mode explicitly labeled, not passed off as live integration.
Q8: Scientific engine blocked result -> blocked reasons retained, no fallback cherry-picking.
Q9: Independent cold start -> documented setup, no dependence on private PHIS repo or personal account; no credentials in repo.
Q10: Sponsor proof -> logs prove real call and returned result, no credentials/PII exposed.
Q11: Provenance manifest every copied/modified file PREEXISTING / ADAPTED / NEW, source commit and licensing approval.
Q12: UI mobile/desktop contrast and keyboard interaction tested, visible loading/error/no-data.
