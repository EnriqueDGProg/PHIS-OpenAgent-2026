# Competition roadmap

## Before official build window — preparation
- [ ] Build rules/eligibility/track/scoring matrix with authoritative source links.
- [ ] Confirm allowed preexisting PHIS dependencies, open-source requirements, sponsor conditions and development tooling.
- [ ] Specify one exemplary evidence-first demo and failure/abstention scenario.
- [ ] Prepare synthetic dataset design, test strategy, security and IP approval.
- [ ] Specify sponsor architecture, interface, pitch storyboard and reproducible installation.
- [ ] Reserve human review only for product quality, approvals and demo.

## During official build window — implementation, subject to confirmed rules
- [ ] Establish source baseline and audit trail for new work.
- [ ] Build and verify agent orchestration and mandatory sponsor integration.
- [ ] Integrate permitted PHIS-derived scientific tooling, with traceability and no user data.
- [ ] Deliver polished judge-facing web interface and safe, deterministic demo dataset.
- [ ] Run evals: tool use, reproducibility, false claims, abstention, UX and privacy.
- [ ] Publish runnable README, architecture diagram, video and pitch deck.

## Release/no-go conditions
- All current official rules satisfied and evidenced.
- No real health data, credentials, private reports or unauthorized code in public repo.
- Demo executes genuine functioning components, never unlabelled canned outputs.
- Evidence provenance and scientific limits visible and correct.
- Submission artifacts complete and tested by a clean-room reviewer.
